# Typography pairing

How to choose type in step 3 of the workflow.

## Start with one family

A single family with enough weights covers most early-stage needs and is hard to get wrong. Add a second family only when a brand attribute calls for contrast the first cannot give.

## If you pair two families

- Contrast them clearly: serif with sans-serif, or a display face with a plain text face. Two similar sans-serifs look like a mistake.
- Give each a job. One for headings, one for body text. Do not mix them inside a paragraph.
- Check that x-heights are close, so mixed lines do not look uneven.

## What to verify for each font

| Check | Why |
| --- | --- |
| License | It must allow the intended use: web, app embedding, print. Read the actual license; do not assume. |
| Weights available | At least regular and bold for body text. |
| Language support | It must cover every language the product ships in, including accents. |
| Numerals | Tabular figures matter for dashboards, pricing and tables. |
| Rendering at small sizes | Body text must stay readable at the smallest size in the scale. |

## Type scale

Pick a base size for body text and a ratio, then derive the steps. Keep the scale short. Five or six sizes are enough for a first identity.

Define for each step: size, line height, weight and the element it is for.

## Usage rules to write down

- Which family and weight for headings, body text, captions and code
- Maximum line length for body text
- Whether uppercase is allowed, and where
- The fallback font stack for each family
