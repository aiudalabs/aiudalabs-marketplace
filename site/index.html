    How it works
    
          
    Five kinds of component. Each one has one job, and the installer knows which ones need which.
    

          
    
            
    Skill
    A how
    Steps, templates and scripts for one task. A folder with a SKILL.md, in the open Agent Skills format.
    
            
    Agent
    A who
    A persona: expertise, judgment and working style. One Markdown file that names the skills it uses.
    
            
    Workflow
    A process
    Phases that call skills and dispatch agents, with gates where you approve before it goes on.
    
            
    Stack
    A bundle
    Everything for one job, installed together. It is only a list, and does nothing at run time.
    
            
    External
    A pointer
    A skill that lives in another repository, cloned at a pinned commit because its license does not allow a copy here.
    
          
    

          
    Who uses whom
    
          
    Installing any piece brings everything it depends on. The arrows below are real dependencies from the catalog.
    
          

          
    What happens when you ask for something
    
          
    A real run of the write-article stack in Claude Code. Skills load into your main conversation. Agents work apart, each in its own context.
    
          

          
    What takes up context, and when
    
          
    You can install many skills without filling the conversation, because each one loads in layers. This is the progressive disclosure the Agent Skills standard defines.
    
          

          
    How it reaches your project
    
          
    The marketplace keeps one version of each component. At install time, an adapter per tool puts it where that tool looks.
